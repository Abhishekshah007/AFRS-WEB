# Content Studio — navigation & roles

How the AFRS admin sidebar is organized and how Super Admins control access.

## Sidebar layout

| Section | Who uses it | What’s inside |
|---------|-------------|----------------|
| **Dashboard** | Everyone with access | Home screen, counts, publishing guide |
| **Inbox** | Super Admin, Content Editor, Event Manager | Website inquiries, course requests, event registrations |
| **Daily content** | Super Admin, Content Editor | Notices, articles, gallery, services, people, etc. |
| **Page copy** | Super Admin, Content Editor | Home, About, Services, Student Hub, site header/footer |
| **Courses & events** | Super Admin, Event Manager | Events, programmes catalog, registration form |
| **Files** | All staff roles | Media library |
| **Staff & access** | Super Admin only | Staff accounts, **Staff menu access** |

The **active** screen shows a wine highlight and a left bar on the current link. The top bar shows the screen title.

## Roles (assign under Staff accounts)

| Role | Typical user | Access |
|------|----------------|--------|
| **Super Admin** | IT / lead | Everything + **Staff menu access** |
| **Content Editor** | Website / notices team | Daily content, page copy, inbox (incl. course **requests**), media |
| **Event Manager** | Programmes team | Events, registrations, programmes catalog, media, inbox |
| **Student** | Learners | No studio menus (do not use for staff) |

Change a person’s role: **Staff & access → Staff accounts** → edit **Role** (Super Admin only).

## Super Admin: hide extra menu items

**Staff & access → Staff menu access**

Add rows per role to **hide** collections or globals on top of the defaults. This only affects the sidebar; API access still follows collection permissions.

After changes, staff may need to refresh the browser.
